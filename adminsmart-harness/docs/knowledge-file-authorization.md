# 知识原件加载、读取与会话授权

知识文件从主应用进入 Harness 后，仍由官方 AttachmentStore、Session、Agent Loop 和文件工具保存、投影及读取。AdminSmart 的职责是确认当前用户、会话和业务范围，不能用服务器任意路径或全局存储中存在文件代替授权。

## 读取链路与权限来源

1. `load_knowledge_files` 使用 FastAPI 能力令牌及可信当前 Session，取得有权访问的原件。
2. 官方 `saveFileStream` / `saveImages` 保存不可变原件，并返回 FileBlock / ImageBlock 引用。
3. 官方 Agent Loop 追加 `tool/call`，随后追加第一类 `tool/result` 消息；结果的 `message.role` 为 `tool`，`toolCallId` 在消息层，附件块直接位于 `message.content`。
4. `sessionFiles` 从真实会话事件派生已授权引用。结果必须匹配同一会话之前的知识加载调用、来源身份、轮次、步骤及官方调用序号，并且没有错误状态。失败、陌生工具、重复结果和派生替换不能新增授权。
5. 官方模型层通过 `fileHostPath` 与 FS provider 给模型投影真实只读路径。原生 `read` 使用这个路径；`sha256:` 是内容身份，资产 UUID 是选择身份，二者都不能作为 `file_path`。文件清单与系统级办公指引共用此规则，已有会话的旧清单不能覆盖当前正确路径指引。
6. AdminSmart Guard 先匹配已授权引用的官方真实路径，再判断普通业务路径。原件只读；业务结果可按既有工作目录规则读写。官方 Store 的硬链接只允许精确授权地址，不能按 inode 或目录扩大访问范围。

此授权集合不写入第二份数据库、不缓存模型声称的文件身份，也不依赖全局 Store 是否存在对象。每次从已接受事件恢复，所以进程重启与 Session 恢复后使用同一规则。官方 Session 负责将 V3 历史包装迁移为规范化 V4 消息；插件不递归解释退役的 `tool-result` 内容。子会话只继承 Host 验证过的直接父会话与自身，不能用父会话的 callId 为自身陌生结果配对。

## 根因与回归要求

原收集器只查找内容中的 `type: 'tool-result'` 包装，漏掉当前官方直接文件块。因此原件成功挂载后，读取仍被误判为未授权。回归须验证真实官方执行链，不能只测试手写的旧包装或单独的工具渲染器。

目标测试使用合成文件、Fake 模型及 Fake 内部 API。覆盖正式调用、失败状态、来源身份、顺序、跨会话、派生替换、直接子会话、官方 Session 恢复，以及根内外原件只读与未知硬链接拒绝。通用原件、文字读取、图片和官方页面渲染共享 `sessionFiles` 权限来源；不得给其中一个工具单独维护平行白名单。

## 发布与验收

本地修改后运行插件 `npm run check` 和受管 `harness-service.ps1 validate`。当前 Gateway 开发与生产共享，修改插件后，已有 Runtime 仍持有旧模块；浏览器刷新不能代替 Runtime 重建。用户执行“更新所有服务”时，受管发布流程会检查共享运行修订并按维护流程切换，之后才验收生产。

发布后可在原会话重新提问或新建会话验证：知识原件加载成功，随后原生读取成功，回答明确标注真实读取范围。历史已失败的消息保留其原始结果，不会被修复代码自动改写。如果文件分页、单次大小或读取窗口限制导致覆盖不全，仍应继续读取或准确说明范围，不能仅因授权成功就声称已核对全部资料。
